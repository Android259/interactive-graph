## 0. Где в коде реально упоминаются BERT и DeepCLIP

Обе статьи в проекте фигурируют не как имплементация, а как название РЕЖИМА
обучения — "одна модель на один белок/семью, обучена и провалидирована только
на его собственных данных":

- `dataloader/Dataloader.py:144` — комментарий у фильтра `--family_only`:
  "the DeepCLIP/BERT-RBP 'one model per protein/family, trained (and validated)
  only on its own data' regime".
- `training/read_configuration.py:1452` — тот же режим у объявления флага
  `family_only`: "Per-article training (DeepCLIP/BERT-RBP: one model per
  protein, trained ONLY on that protein's own data)".
- `architecture/interaction_classification.py:62` — при описании
  `protein_recon_head` (голова структурного предобучения): "BERT-RBP's own
  masked-token head is a single linear layer too — depth belongs in the
  backbone, not here" — то есть BERT здесь цитируется уже не про сплит, а про
  АРХИТЕКТУРУ маскированной головы.
- `files/structural_pretrain_family_diagnosis.md:17` — то же самое как вывод
  независимого разбора: `structural_pretrain_family` — это "the 'one model per
  family/protein' regime (DeepCLIP/BERT-RBP-style)".

Сами статьи (общеизвестные, не найдены как файлы в репозитории):

- **BERT** — Devlin et al., *BERT: Pre-training of Deep Bidirectional
  Transformers for Language Understanding*, NAACL 2019 (arXiv:1810.04805).
- **DeepCLIP** — Grønning et al., *DeepCLIP: predicting the effect of
  mutations on protein–RNA binding with deep learning*, Nucleic Acids Research
  48(13), 2020.
- **BERT-RBP** (то, что код цитирует буквально) — дообученный BERT поверх
  РНК-токенов, по одному белку (RBP) за раз на его собственных eCLIP-данных;
  упомянут в коде как второй пример того же режима, что и DeepCLIP, не как
  отдельная архитектура для переноса сюда.

## 1. Как они устроены (коротко, по сути, что переносимо на липиды)

**BERT.** Трансформер-энкодер без каузальной маски (внимание видит весь ряд
токенов сразу в обе стороны). Предобучение — Masked Language Modeling: 15%
токенов маскируются, модель предсказывает их по контексту; получается
контекстный эмбеддинг на каждый токен плюс сводный вектор всей
последовательности. Дообучение — на верх замороженного или размораживаемого
энкодера навешивается маленькая голова под конкретную задачу, обучается на
небольшом размеченном наборе. Ключевая идея — перенос: дорогое предобучение на
огромном неразмеченном корпусе один раз, дешёвая доводка много раз.

**DeepCLIP.** Один БЕЛОК — одна модель, обучена и провалидирована только на
его собственных связанных/несвязанных последовательностях (ровно то, что код
проекта цитирует). Архитектура: one-hot нуклеотидная последовательность → 1D
свёртка (сканер локальных мотивов, по сути обучаемая PWM) → двунаправленный
LSTM (порядок/контекст вдоль последовательности) → attention-слой, который
считает вес на каждой позиции и суммирует скрытые состояния во ОДИН вектор →
сигмоида (вероятность связывания). Главная фишка DeepCLIP — не сам факт
хорошего скора, а то, что веса attention-слоя ЧИТАЕМЫ как профиль по позициям:
из них строится sequence-logo связывающего мотива и карта результата in silico
мутагенеза (какая замена нуклеотида сильнее всего меняет предсказание).

Для липидной ветки это значит: DeepCLIP — это "локальный сканер паттернов +
внимание, которое можно прочитать как профиль по токенам", а не что-то
специфичное для РНК-алфавита. Canonical SMILES — тоже последовательность
токенов (атом/связь/скобка/цифра кольца), и она уже токенизируется в проекте
точно так же.

## 2. Что из этого УЖЕ есть в липидной ветке — по коду

- **Входные данные — уже canonical SMILES как последовательность токенов.**
  `preprocessing/embed_isomeric_smiles_molformer.py:32-36` канонизирует изомерный
  SMILES (`Chem.MolToSmiles(..., canonical=True, isomericSmiles=True)`), токенизирует
  `MolTranBertTokenizer` (свой BPE-подобный словарь под химию, `bert_vocab.txt`,
  строка 21) и прогоняет через MoLFormer — химический BERT (трансформер,
  предобучен маскированием токенов на ~1 млрд SMILES из PubChem, IBM). Результат —
  тензор `(1, tokens, 768)` на молекулу (`dataloader/lipid_graph_builder.py:210`),
  это и есть `lipLM`, приходящий в `architecture/lipid_encoder.py`.
- **BERT в проекте уже используется дважды**, оба раза заморожен:
  1. Снаружи — MoLFormer как фиксированный источник эмбеддинга токена SMILES
     (описано выше).
  2. Внутри — `--structural_pretrain`, собственный BERT-стиль проекта, но
     ТОЛЬКО на белковой башне: маскирует 15% геометрических признаков остатка
     (`dataloader/Dataloader.py:2095-2125`, `_mask_residue_features`), учит
     `protein_recon_head` (`architecture/interaction_classification.py:70-74`)
     восстанавливать их по MSE (`training/new_train.py:1429-1437`), чекпоинт
     потом грузится и замораживается через `--pretrained_checkpoint
     --freeze_pretrained_encoders` (`training/new_train.py:108-146`). На
     липидную башню (`lipid1`) это предобучение сегодня не распространяется —
     не потому что не влезает технически (`load_state_dict(..., strict=False)`
     на строке 120 грузит ЛЮБЫЕ совпадающие ключи всей модели, не только
     `protein1.*`), а потому что заморозка на строке 145 жёстко называет
     `model.protein1.parameters()`, и потому что ни один существующий скрипт
     предобучения не запускает такую стадию для `lipid1`.
- **Режим "одна модель — одна семья" уже реализован** — `--family_only`
  (раздел 0 выше). Ничего нового для этой части писать не нужно.
- **Кусок DeepCLIP-attention уже есть, но без выхода "профиля".**
  `--attention_pooling` строит `AttentionPool` (`architecture/final_layer.py:
  138-160`) отдельно для липида и для белка: линейный gate на каждый токен →
  softmax ПО ТОКЕНАМ ОДНОЙ МОЛЕКУЛЫ (`scatter_softmax(logit, batch)`) →
  взвешенная сумма токенов в один вектор. Это механически ТО ЖЕ САМОЕ, что
  attention-слой DeepCLIP делает над состояниями BiLSTM — с одной разницей:
  вес `alpha` (строка 159) считается и тут же выбрасывается, наружу возвращается
  только сумма (`_pool_partners`, `final_layer.py:667-681`). Профиля по токенам
  — DeepCLIP-шного "что подсветила модель" — сегодня для липида нет вообще: то,
  что есть у белка (маскированная реконструкция, `structural_pretrain`) — это
  вспомогательная self-supervised задача, а не saliency по финальному классу.
- **Чего нет вовсе — локального сканера мотивов и явного порядка вдоль
  последовательности.** Единственное перемешивание токенов между собой — один
  блок self-attention (`--lipid_self_attention`, `architecture/self_attention.py`,
  вызывается из `Lipid_encoder.forward`, `architecture/lipid_encoder.py:260-277`).
  Ни свёртки (сканер локального фрагмента в несколько соседних токенов — кольцо,
  функциональная группа), ни рекуррентного слоя (явный порядок токенов) в
  липидной ветке нет.

## 3. Предложение: три независимых, опциональных куска

Все три — по образцу проекта: новые флаги, ничего не трогают в конфигурациях,
которые их не выставляют. Все три имеют смысл именно под `--family_only=<семья>`
— это тот самый DeepCLIP/BERT-RBP режим, который код уже называет по имени, и
именно там задача "найти паттерн, специфичный для известных белков одной
семьи" не смешивается с вопросом про cold-split на новую химию — это разные,
непересекающиеся эксперименты (см. [[project_lipid_coldsplit_primary]]:
липидный колдсплит — отдельная, уже идущая ось, метрика там —
`AUC_within_protein_pairs` по [[project_lcs_primary_metric]], и путать эти два
режима не стоит).

**3.1. Локальный сканер мотивов — `--lipid_conv_kernel=<k>` (аналог свёртки
DeepCLIP).** Conv1d (или несколько параллельных с разными k, например 3/5/7)
поверх `lipLM` внутри не-графового пути `Lipid_encoder` (`architecture/
lipid_encoder.py:105-172`), ДО `self.encodin`/self-attention. Смысл — то же,
что у DeepCLIP: не общий трансформер сразу глобально смешивает все токены, а
сначала маленькое окно из нескольких соседних SMILES-токенов (открывающая
скобка + цифра кольца + атом, или последовательность атомов сложноэфирной
группы) даёт локальный признак "здесь такой-то фрагмент". Технический нюанс,
который нужно решить перед реализацией: при `--lipid_concat`/
`--lipid_fragments_mask` несколько кандидатов-SMILES кладутся ПОДРЯД по оси
токенов одного графа (`dataloader/lipid_graph_builder.py:206-218`,
docstring: "lay the candidates out along the token axis... composes without
padding"), а `mult_mask` потом ограничивает self-attention рамками одного
кандидата (`architecture/self_attention.py:61-66`). Plain `Conv1d` по всей
склеенной последовательности будет протекать через границу кандидатов —
свёртку нужно делать через `to_dense_batch` ПО КАЖДОМУ фрагменту отдельно (тот
же паттерн, что `SlicedWassersteinPool` уже использует, `architecture/
final_layer.py:216-226`), а не как один плоский тензор.

**3.2. Явный порядок (по желанию, не приоритет) — `--lipid_sequence_model=lstm`.**
BiLSTM/BiGRU поверх результата 3.1, вместо или перед `--lipid_self_attention`.
Технически прямой перенос DeepCLIP. Приоритет ниже, чем у 3.1 и 3.3: то, что
DeepCLIP в 2020 году выбрал именно BiLSTM, а не self-attention — архитектурный
выбор своей эпохи, а не то, без чего идея "искать паттерн" не работает; в
проекте уже есть self-attention-блок, который решает задачу перемешивания по
порядку не хуже, и добавлять сюда ещё и LSTM — это лишняя сущность, если 3.1
и 3.3 уже дают то, ради чего обычно берут DeepCLIP (мотив + читаемость).

**3.3. Прочитать `alpha` наружу — САМАЯ прямая аналогия DeepCLIP, отсутствующая
сейчас.** `AttentionPool.forward` (`final_layer.py:155-160`) уже считает
per-токенный вес `alpha = scatter_softmax(logit, batch)` — нужно только не
выбрасывать его, а вернуть (например `return_weights=True`, тем же паттерном,
что `compute_adversary` уже складывает промежуточный результат в `self._adv`
для тренировочного цикла, `final_layer.py:683-694`). Дальше — маленький скрипт
по образцу `analysis/checkpoint_scores.py`, который для обученного
`--family_only` чекпоинта сопоставляет `alpha` с текстом токена (тот же
`MolTranBertTokenizer`, что уже используется в `preprocessing/
embed_isomeric_smiles_molformer.py:88`) — это и есть DeepCLIP-шный "профиль
связывания", только по фрагментам SMILES вместо нуклеотидов: какой кусок
кандидата-липида (голова, конкретная связь, кольцо) поднял или опустил
предсказание.

**3.4. (Крупнее, по образцу уже существующего `structural_pretrain`) —
маскированное предобучение SMILES-токенов на липидной башне.** Маскировать
часть токенов `lipLM` перед `lipid1`, учить голову восстанавливать либо сам
768-мерный вектор (MSE — по образцу белковой стороны), либо ID токена в
словаре `MolTranBertTokenizer` по cross-entropy (это ближе к настоящему BERT
MLM, чем к тому, что сейчас сделано для белка). Обучается один раз, без метки
`Interaction`, на всех семьях сразу — как сейчас `--structural_pretrain`
(`training/read_configuration.py:1438-1441`). Чекпоинт грузится тем же
`--pretrained_checkpoint` (он и так подхватит `lipid1.*` ключи, раз
`load_state_dict` не фильтрует по префиксу — `training/new_train.py:120`), но
`--freeze_pretrained_encoders` сегодня замораживает только `protein1`
(`new_train.py:144-146`) — нужна одна дополнительная строка (заморозка
`lipid1`, за отдельным флагом или расширением существующего). Это самый
дорогой из четырёх пунктов и не обязателен для того, чтобы получить
DeepCLIP-подобную читаемость — 3.1+3.3 достаточно для профиля мотива без
предобучения.

## 4. Открытые вопросы (не измерено, не выбрано)

- MSE на непрерывном эмбеддинге токена или cross-entropy на ID токена — какая
  маскированная задача лучше для 3.4 — не решено, ни один вариант не прогонялся.
- Ширина свёртки/скрытый размер LSTM в 3.1/3.2 — вопрос, специфичный для
  SMILES-алфавита (короче слов, длиннее нуклеотидов), не выводится напрямую из
  того, что DeepCLIP использует для РНК.
- `--lipid_graph_isomers` (графовый путь, GATv2 по атомам/связям,
  `lipid_encoder.py:45-104`) и не-графовый путь токенов (`lipid_encoder.py:
  105-172`) в `Lipid_encoder.__init__` взаимоисключающие (`if ... else`) — весь
  раздел 3 применим только к не-графовому пути; совмещать граф и
  DeepCLIP-скан токенов одновременно — отдельная, не рассмотренная здесь
  задача.
- Выигрыш 3.1-3.3 не измерялся — предложение архитектурное, не результат
  прогона.
