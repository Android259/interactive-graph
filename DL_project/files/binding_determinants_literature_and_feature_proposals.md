# Что литература считает определяющим в связывании LTP-липид, и каких признаков нам не хватает

Снимок на 2026-09-19. Веб-ресёрч по статье-источнику данных и по смежным работам, плюс
сверка с тем, что уже считается в проекте (`dataloader/pair_descriptors.py`,
`training/pair_baseline_common.py`, `data/graphs/<белок>/coarse_graph_nodes.csv`).

## 1. Статья-источник (Titeca, Gavin и др.)

Препринт bioRxiv 2023 (`files/Reuter.pdf`) вышел в Nature в 2026 в расширенном виде.
Что там названо определяющим:

- **Объём кармана против объёма липида.** Единственное явное количественное
  соотношение «карман × липид» в самой статье. 35 LTP, 213 известных пар + 173 новых.
- **Длина ацильной цепи различается точно.** CERT связывает церамиды 32-36 углеродов
  и НЕ связывает 40-42, хотя последние в клетке в избытке. Это не «предпочтение», а
  дискриминация по размеру.
- **Предпочтение коротких, моно- и ди-ненасыщенных липидов** — тех, что создают
  глубокие дефекты в мембране. То есть ненасыщенность важна не сама по себе, а через
  геометрию.
- **Специфичность двухкомпонентна:** «recognition of specific head groups, but also of
  specific fatty acids». Голова и хвост — два независимых канала узнавания.

Чего в статье НЕТ: собственных дескрипторов кармана, коэффициентов корреляции,
QSAR-анализа. Она отвечает «какие липиды связываются», а не «почему».

## 2. Смежные работы

**SLiPP (J. Chem. Inf. Model., 2025)** — Random Forest на 17 дескрипторах fpocket,
8380 карманов, accuracy 96.8%. Важнейший для нас результат — отрицательный:

> «no distinction is apparent when considering the individual lipids, which suggests
> that the pocket properties described by fpocket are not sufficient to detect
> differences between the selected lipids»

То есть независимая работа на большой выборке установила: **generic-дескрипторы
кармана отличают липид-связывающий карман от нелипидного, но НЕ отличают, какой
именно липид он свяжет.** Это ровно наша задача и ровно наша трудность. Наши
`AUC_in_protein` 0.53-0.73 — не признак плохой реализации, а ожидаемый потолок для
этого класса признаков.

Что у них вышло в топ важности: **hydrophobicity score** и **mean local hydrophobic
density**, третьей — площадь поверхности. Их остальные категории: alpha-sphere метрики
(solvent accessibility, density, max distance), polarity score, charge score,
flexibility.

**Литература по узнаванию головной группы** (FEBS Lett. 2010; PLOS Comput. Biol. по
PH-доменам): анионные головы узнаются **прямыми электростатическими контактами с
основными остатками** (Lys, Arg). PH-домены находят PIP среди ~20% анионных липидов
именно электростатикой. Отдельно отмечается, что специфичность части белков выходит
за пределы электростатики — работают форма, глубина и комплементарность кармана.

## 3. Главная находка сверки: у нас УЖЕ посчитана химия кармана, но она не в пуле

`training/pair_baseline_common.py` считает `POCKET_CHEMISTRY_NAMES` —
десять долей по остаткам кармана, отдельно для ядра и для устья:

    basic_share_core / basic_share_rim
    acidic_share_core / acidic_share_rim
    polar_share_core / polar_share_rim
    hbond_donor_share_core / hbond_donor_share_rim
    hbond_acceptor_share_core / hbond_acceptor_share_rim

**Ни один из этих десяти не входит в `PROTEIN_DESCRIPTOR_NAMES`** (проверено прямым
сравнением), а именно этот список — пул, по которому идёт весь отбор признаков.
То есть поиск их никогда не видел.

При этом `basic_share_rim` — это буквально «сколько Lys/Arg на устье кармана», то есть
прямая мера того механизма, который литература называет главным для узнавания анионных
голов (PG, PA, PS, PI, PGP — пять из наших девяти групп анионные). А деление
core/rim совпадает с двухканальностью из статьи-источника: устье узнаёт голову, ядро
упаковывает хвост.

**Предложение 1 (нулевая цена, наибольшая ожидаемая отдача): включить
`POCKET_CHEMISTRY_NAMES` в пул отбора.** Ничего считать не надо — значения уже
вычисляются. Пул белковых становится 30 вместо 20.

## 4. Чего не хватает по сравнению с литературой, и что можно посчитать из наших данных

Доступное сырьё на белок (`coarse_graph_nodes.csv`, 26 колонок на остаток):
`residue_type`, `residue_sas_area`, `residue_volume`, `residue_voromqa_sas_energy`,
`residue_mean_voromqa_depth`, `voromqa_score_r`, min/max/mean по `ev14`, `ev28`,
`ev56`, `buriedness`. Плюс `pocketness.pdb` с координатами атомов кармана.

| Признак из литературы | Есть у нас? | Можно посчитать из имеющегося? |
|---|---|---|
| hydrophobicity score (топ-1 у SLiPP) | частично: `hydropathy_core/rim/mean` | да, но это оно и есть |
| **mean local hydrophobic density** (топ-2 у SLiPP) | **нет** | **да** — средняя гидрофобность соседей по графу для каждого гидрофобного остатка кармана, `coarse_graph_links.csv` даёт соседство |
| **charge score / суммарный заряд кармана** | нет (есть basic/acidic по отдельности, и те вне пула) | **да** — `basic_share − acidic_share`, тривиально |
| **электростатика устья** | нет | частично — суммарный формальный заряд остатков устья; полноценный потенциал Пуассона-Больцмана потребовал бы APBS, его нет |
| alpha-sphere метрики (density, max distance) | нет | да — из координат `pocketness.pdb`, но это дублирует `pocket_extent`/`elongation` |
| **flexibility кармана** | нет | **да** — `voromqa_score_r` и `residue_voromqa_sas_energy` уже есть на остаток, их дисперсия по карману = мера рыхлости |
| объём кармана vs объём липида | **как ПАРНЫЙ** `volume_fit` | да, но см. §5 — Kron-RLS его принять не может |
| длина цепи vs глубина кармана | как парный `chain_extent_gap` | то же ограничение |

**Предложение 2: посчитать `local_hydrophobic_density`** (топ-2 признак у SLiPP, у нас
отсутствует). Для каждого остатка кармана — средняя гидрофобность его соседей по
`coarse_graph_links.csv`, затем среднее по карману. Отличается от
`hydropathy_mean` тем, что ловит КЛАСТЕРИЗАЦИЮ гидрофобных остатков, а не их долю:
карман с одним сплошным гидрофобным пятном и карман с той же долей, но вразброс,
дают одинаковый `hydropathy_mean` и разный local density.

**Предложение 3: `pocket_net_charge`** = `basic_share − acidic_share` (и отдельно для
устья). Одно число вместо двух долей, прямо соответствует «charge score» из набора
fpocket и механизму узнавания анионных голов.

**Предложение 4: `pocket_rigidity`** = дисперсия `voromqa_score_r` по остаткам кармана.
Аналог flexibility из fpocket; сырьё уже в таблице остатков.

## 5. Структурное ограничение, которое стоит назвать прямо

Самое обоснованное литературой соотношение — **объём липида против объёма кармана**
(это то, что меряет сама статья-источник) — является ПАРНЫМ признаком: значение
определено для комбинации (белок, липид), а не для одной стороны. У нас оно уже
реализовано (`volume_fit` в `PAIR_DESCRIPTOR_NAMES`, вместе с `chain_extent_gap`,
`hbond_match`, `buriedness_match`, `depth_bulk_match`, `hydropathy_chain_match`,
`elongation_shape_match`, `flatness_shape_match`).

**Kron-RLS не может их использовать в принципе.** Его замкнутая форма
`A = (Kp+λI)⁻¹Y(Kl+λI)⁻¹` требует двух СЕПАРАБЕЛЬНЫХ ядер; парное значение не
раскладывается ни в одно из них (`scripts/run_cron.py` отказывает на `--pair_features`
именно с этим объяснением).

Практический вывод: **признак, который литература считает главным, недоступен текущей
модели по устройству метода.** MLP таких ограничений не имеет — он принимает
конкатенацию любых признаков, включая парные. Это отдельный аргумент за переход на
MLP, независимый от качества метрик, и повод не считать текущий потолок
`AUC_in_protein` окончательным.

## 6. Итог — что предлагается сделать

1. **Включить `POCKET_CHEMISTRY_NAMES` (10 признаков) в пул отбора.** Цена — ноль,
   значения уже считаются; покрывает главный механизм из литературы (узнавание
   анионных голов основными остатками) и двухканальность core/rim из статьи-источника.
2. **Добавить `local_hydrophobic_density`** — топ-2 признак независимой работы, у нас
   отсутствует, считается из уже имеющегося графа соседств.
3. **Добавить `pocket_net_charge`** (и вариант по устью) — аналог charge score.
4. **Добавить `pocket_rigidity`** — аналог flexibility, сырьё есть.
5. **Держать в виду**, что парные признаки (`volume_fit`, `chain_extent_gap`) — самые
   обоснованные литературой — заработают только на MLP, не на Kron-RLS.

После пунктов 1-4 пул белковых станет ~33 вместо 20. Это МЕНЯЕТ арифметику перебора
(§ скрипта `analysis/exhaustive_descriptor_search.py`): предфильтр по корреляциям
становится обязательным, иначе пул не сократить до перебираемого размера.
