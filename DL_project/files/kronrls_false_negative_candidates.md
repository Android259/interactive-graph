# Kron-RLS: поиск кандидатов в false negative по сходству

Снимок на 2026-09-03. Метод: `analysis/kronrls_baseline.py` (существующий, без
изменений) + новый `analysis/kronrls_false_negative_candidates.py`. Данные:
интеракционная таблица после пересборки 2026-08-24 (9905 строк / 634 позитива /
283 вида липидов, [[table-rebuilt-2026-08-24]]).

> **Правило сопровождения**: числа ниже — снимок одного конкретного запуска с
> конкретным протеиновым/липидным ядром и конкретными порогами атрибуции. Другое
> ядро, другая таблица или другие пороги — пересчитать, не дописывать рядом.

## 1. Зачем и что это

Вопрос: можно ли до всякой мокрой валидации предположить, какие из непомеченных
(`Interaction=0`, что в PU-постановке проекта означает "не проверено", а не
"подтверждённый негатив") пар белок-липид на самом деле являются false negative —
то есть протеин реально связывает этот липид, просто эта пара не была
проверена/зарегистрирована? Ответ строится на классическом двухшаговом Kron-RLS
(van Laarhoven et al. 2011; Pahikkala et al. 2014), который в проекте уже был
реализован как независимый non-neural baseline.

## 2. Метод

### 2.1 Модель

Closed-form kernel ridge regression:

```
A = (Kp + λp·I)⁻¹ · Y · (Kl + λl·I)⁻¹
```

где `Kp` — ядро сходства белков, `Kl` — ядро сходства липидов, `Y` — полная
прямоугольная матрица меток train-блока (`training.pair_baseline_common.
aggregate_pair_labels`). Любая пара, включая с белком и/или липидом, не видевшим
train вовсе, оценивается out-of-sample-расширением: `Kp_query,train @ A @
Kl_train,query`.

### 2.2 Выбор ядер

- **Липидное ядро: Tanimoto** (`--lipid_kernel tanimoto`) — сходство по
  молекулярным отпечаткам, дефолт проекта.
- **Белковое ядро: `pocket_subset` с family-neutral набором дескрипторов**, а не
  дефолтный `pocket13`/`pocket23`:
  ```
  --protein_kernel pocket_subset
  --protein_descriptor_names=pocket_volume_per_sasa,pocket_elongation,pocket_flatness,
      buriedness_q50,apolar_sasa_share,aromatic_share,hydropathy_rim
  ```
  Это тот же 7-дескрипторный набор, что и `POCKET_DESCRIPTOR_FAMILY_NEUTRAL_NAMES`
  (`dataloader/protein_graph_builder.py:64-67`) — дескрипторы, чей η² против
  9-семейного сплита сидит на уровне шумового пола (0.28-0.32), а не протечные
  `pocket_extent`/`hydropathy_core`/`depth_q10` (η² 0.55-0.85, почти фингерпринт
  35-белкового набора). Причина принципиальная: если белковое ядро несёт
  family-identity, "найденные" кандидаты будут смещены к "любая непроверенная пара
  из семьи, которое вообще много связывает" — тот же лик, что документирован в
  [[four-families-audit-2026-08-31]] и [[descriptors-path-fingerprint-leak]], только
  теперь на стороне детектора, а не сети.

### 2.3 Честная out-of-sample оценка через leave-one-family-out

`analysis/kronrls_false_negative_candidates.py` прогоняет `--split_mode double`
(double_coldsplit, как и у нейросети) по очереди для каждого из 7 семейств
(CRAL-TRIO, GLTP, IP_trans, LBP_BPI_CETP, START, lipocalin, scp2) × 5 сидов.
Когда семейство X держится вне train, ВСЕ его пары (включая и известные позитивы,
и непомеченные) оцениваются моделью, которая X вообще не видела — честный
out-of-sample скор, не переобученный в него. По кругу через все 7 семейств
результат покрывает весь датасет. λp/λl выбираются по `--lambda_grid` через
PU-AUC на validation-половине held-out блока (см. `evaluate_block` в
`kronrls_baseline.py`), только затем test-половина оценивается выбранными
значениями — подбор регуляризации не подглядывает в test.

### 2.4 Атрибуция: три независимых регулятора строгости

Прямого способа проверить "это действительно false negative" нет (иначе это было
бы просто известным позитивом). Поэтому вместо одного жёсткого порога — три
раздельных, настраиваемых рычага, все три обязаны выполниться одновременно:

| флаг | дефолт | смысл |
|---|---|---|
| `--positive_percentile` | 0.9 | порог = этот перцентиль **скора известных позитивов** (out-of-sample, из тех же блоков) — 0.9 значит "так же уверенно, как топ-10% реальных позитивов" |
| `--min_family_auc` | 0.65 | семьи с held-out test_auc ниже этого **не участвуют вообще**, не просто помечаются — near-chance AUC значит, что ранжирование в этой семье не несёт сигнала |
| `--min_seed_consistency` | 0.8 | пара должна проходить порог минимум в этой доле сидов, а не только в среднем — защита от случайной "удачи" одного переобучившегося сида |

Порог считается **только** по известным позитивам, никогда по самим кандидатам —
ужесточение `--positive_percentile` может только повышать строгость, не может
подгонять ответ под данные, которые ищет.

## 3. Результат прогона (2026-09-03, дефолтные пороги)

Команда:
```
python3 analysis/kronrls_false_negative_candidates.py \
    --protein_kernel pocket_subset \
    --protein_descriptor_names=pocket_volume_per_sasa,pocket_elongation,pocket_flatness,buriedness_q50,apolar_sasa_share,aromatic_share,hydropathy_rim \
    --lipid_kernel tanimoto --lambda_grid 0.01,0.1,1,10,100
```

### 3.1 Надёжность ранжирования по семьям (held-out test AUC, mean по 5 сидам)

| family | test_auc |
|---|---|
| GLTP | 0.797 |
| lipocalin | 0.766 |
| LBP_BPI_CETP | 0.689 |
| scp2 | 0.676 |
| START | 0.535 |
| IP_trans | 0.533 |
| CRAL-TRIO | 0.525 |

CRAL-TRIO/IP_trans/START — около случайного уровня, при дефолтном
`--min_family_auc=0.65` исключены из атрибуции целиком (их кандидаты не несут
сигнала, каким бы ни был их сырой скор).

### 3.2 Атрибуция на дефолтных (максимально консервативных) порогах

```
known positives scored (threshold source):              514
unlabeled pairs scored (full candidate pool):            2503
  -- from families clearing --min_family_auc:            1292
attributed false-negative candidates (all 3 gates pass): 0
```

**Ноль атрибутированных кандидатов.** Это не сбой скрипта: порог P90 от известных
позитивов = 0.2515, а даже топовый кандидат среди надёжных семей (`HSDL2` ×
`Lysophosphatidylcholine (18:1)`, scp2, family test_auc=0.68) даёт `mean_score
=0.049` — почти в 5 раз ниже порога. Ни один из 1292 кандидатов из надёжных семей
не проходит даже первый гейт (`score_high_enough`: 0/1292); `seed_consistency`
до проверки не доходит вовсе — узкое место чисто в масштабе скора, не в
согласованности между сидами.

### 3.3 Интерпретация

Два равновозможных объяснения, метод сам по себе их не различает:

1. В этом датасете при этой паре ядер действительно нет пар, которые выглядели бы
   "так же уверенно, как топ-10% настоящих позитивов" — то есть сильных false
   negative просто мало или нет.
2. Out-of-sample-скор для по-настоящему невиданной (cold-family) пары структурно
   сжат относительно скора известных позитивов той же процедуры — типичное
   поведение Kron-RLS-экстраполяции на разреженных семьях (напоминание:
   LBP_BPI_CETP всего 2 белка, ELP1 таких множится по всем семьям).

Полный скор всех 2503 пар (включая непрошедшие любой из трёх гейтов и
исключённые по `--min_family_auc`) сохранён в `/tmp/.../scratchpad/
kronrls_candidates.csv` данного запуска (временный путь, не в репозитории) —
воспроизводится командой из §3 плюс `--out <path>`.

## 4. Как ослаблять пороги (и чего не делать)

- Понижение `--positive_percentile` (например до 0.7) — самый прямой рычаг,
  раз главное узкое место в §3.2 именно в `score_high_enough`.
- Понижение `--min_family_auc` вернёт в пул кандидатов из CRAL-TRIO/IP_trans/
  START — не рекомендуется: там ранжирование около случайного, кандидаты оттуда
  статистически неотличимы от случайного списка.
- **Не использовать полученный список для жёсткой релейбловки** (0→1 в датасете
  впрямую). Правильное использование — приоритетный список для мокрой проверки,
  либо мягкий prior в PU-лоссе (nnPU/rho, [[pu-nnpu-underfits-train]]).
- Перед тем как доверять любому шортлисту (особенно из семей с высоким test_auc
  вроде GLTP/lipocalin) — прогнать `analysis/chemistry_null_model.py`: protein-blind
  Tanimoto-ближайший-сосед может давать похожий на вид ранжированный список по
  совершенно другой причине (химический маргинал, не выученная пара
  белок-липид) — тот же механизм, что объяснил "победы" GLTPD1/PITPNC1 в
  [[working-triple-explains-protein-wins]].
