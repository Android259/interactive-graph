## 1. Где сеть стоит на самом деле

Планка «белок × подкласс» мерена на **настоящих** test-кадрах базовой конфигурации
(5 сидов × ~145 строк, сэмплирование негативов как в ране), а не на полной таблице:
приор ячейки `(LTPProtein, подкласс статьи)` оценивается на трейне, порог 0.5,
непокрытые ячейки падают на общий приор.

| | тест BA | тест F1 |
|---|---:|---:|
| приор ячейки, оценённый на трейне | **0.871 ± 0.009** | **0.832 ± 0.015** |
| **сеть `ge_s15_prothid32_hid64_noreg`** | **0.902 ± 0.025** | **0.861 ± 0.036** |
| оракул ячейки (приор оценён по самим test-строкам) | 0.935 | — |

По сидам приор даёт 0.875 / 0.841 / 0.896 / 0.872 / 0.870; оракул 0.969 / 0.847 /
0.963 / 0.959 / 0.938.

Разница сети и приора — **+0.031** по BA и **+0.029** по F1. Медиана разброса
повторного прогона того же label на том же сиде — 0.021, максимум 0.057
([ge_s15_architecture_sweep_results.md §3](ge_s15_architecture_sweep_results.md)).
То есть превышение есть, но оно того же порядка, что шум одного прогона: сеть **едва**
выше угадывания по «белок × подкласс», а не уверенно выше. Для сравнения, вся разница
между 29 вариантами архитектуры этого порога не проходит вообще.

Оракул ячейки 0.935 — потолок любого предиктора, видящего только пару
(белок, подкласс). Он не 1.0 именно потому, что часть ячеек смешана.

## 2. Из чего состоит разрыв 0.871 → 0.935 → 1.0

Пулом по 5 сидам: 723 test-строки, 242 позитива.

**(а) Непокрытые ячейки — 10.1% строк, но почти все негативы.**

| | строк | поз | BA приора |
|---|---:|---:|---:|
| ячейки нет в трейне | 73 (10.1%) | 7 (2.9% всех) | **0.500** |
| ячейка есть в трейне | 650 (89.9%) | 235 (97.1%) | 0.877 |

BA на них 0.500, но весят они мало: позитивов там 7 из 242. Прямая проверка — выбросить
непокрытые строки из теста целиком: приор поднимается всего **0.871 → 0.879** (valid:
0.866 → 0.870), доля позитивов в блоке 0.335 → 0.362, остаётся 90.0% строк и 97.3%
позитивов (valid+test, 1303 из 1447 строк, 471 из 484 позитивов). В долях полной
таблицы блок на сид падает с 0.153 до 0.149 позитивов.

То есть **это не главный запас**, как можно было подумать по одной цифре 0.500.

Реализовано флагом `--drop_uncovered_protein_subclass` (только вместе с
`--lipid_species_coldsplit`; ключ ячейки — тот же, что в
`analysis/protein_subclass_label_baseline.py`, чтобы сеть и планка считались на одних
строках). Фильтр применяется к блоку до деления пополам по метке, train не трогает,
и добавляет `_covered` к имени каталога исключающего набора. Конфигурация
`scripts/arg_files/ge_s15_prothid32_hid64_noreg_covered.md` — флаг в флаг базовая, плюс
эта строка. Проверено на сплите: test 723 → 652 строки (−9.8%) и 242 → 235 позитива
(−2.9%), valid 724 → 651 (−10.1%) и 242 → 236 (−2.5%), доля позитивов 0.335 → 0.360,
покрытие ячеек 100.0% на всех пяти сидах, train побайтово тот же. Планка на новом
label: **0.878 ± 0.011** BA, 0.841 ± 0.018 F1 (предсказывалось 0.879). Ничего не
обучалось.

**(б) Чем БОЛЬШЕ трейн-строк в ячейке, тем ХУЖЕ приор.**

| трейн-строк в ячейке | строк теста | поз | BA приора |
|---|---:|---:|---:|
| 1 | 73 | 10 | 0.942 |
| 2 | 65 | 10 | 0.700 |
| 3–4 | 93 | 26 | 0.923 |
| 5–9 | 143 | 39 | 0.905 |
| 10+ | 276 | 150 | **0.820** |

Контринтуитивно, но объяснимо: крупная ячейка — это белок, который внутри одного
подкласса берёт одни виды и не берёт другие. Там живёт **150 из 242** позитивов, и
именно там приор обязан ошибаться.

**(в) Смешанные ячейки.** 94 строки (13.0%) несут 45 позитивов — **18.6% всех
позитивов теста**. Ни один предиктор уровня ячейки их не возьмёт.

## 3. Что различает метку внутри ячейки

`within-cell AUC` — доля пар (позитив, негатив) **из одной ячейки**, упорядоченных
признаком верно. 0.5 = признак не добавляет к «белок × подкласс» ничего; отклонение в
любую сторону = добавляет (знак — это направление, не качество). Считано на полной
таблице, где мощность есть: 76 ячеек с обоими классами, 13 739 пар, 536 из 634
позитивов.

| дескриптор | within-cell AUC | pooled AUC | |
|---|---:|---:|---|
| `tail_double_bond_position` | **0.651** | 0.503 | ортогонален маргиналу |
| `unsaturation` | 0.356 | 0.467 | позитивы МЕНЕЕ насыщены |
| `tail_double_bonds` | 0.360 | 0.468 | |
| `tail_unsaturation_density` | 0.362 | 0.496 | |
| `tail_length_mean` | 0.391 | 0.439 | позитивы КОРОЧЕ |
| `chain` | 0.392 | 0.432 | |
| `tail_heavy_atoms` | 0.408 | 0.429 | |
| `heavy` | 0.409 | 0.464 | |
| `tpsa` | 0.589 | 0.498 | позитивы полярнее |
| `experimental_lipid_volume` | 0.412 | 0.469 | |
| `molar_refractivity` | 0.415 | 0.457 | |
| `hbond` | 0.566 | 0.488 | |
| `npr1` | 0.430 | 0.509 | |
| `logp` | 0.438 | 0.490 | |
| `tail_length_asymmetry` | 0.527 | 0.466 | |
| `ring_count`, `aromatic_ring_count` | 0.499 / 0.500 | | ничего |

Читается так: **хвост несёт сигнал, которого нет в маргинале**. У всех сильных строк
pooled AUC сидит около 0.5 — то есть признак не коррелирует с меткой «в среднем по
таблице», но упорядочивает её внутри ячейки. Это по определению информация сверх
«белок × подкласс».

Самый сильный — положение двойной связи, и он же единственный, у кого отклонение
направлено вверх.

## 4. `tail_double_bond_position`: устойчивость и один подвох

Устойчивость (только ненасыщенные виды, см. ниже почему):

| проверка | значение |
|---|---|
| within-cell AUC | **0.672** на 10 817 парах |
| ячеек с AUC > 0.5 | 44 из 76 |
| медиана по ячейкам (невзвешенно) | 0.591 |
| без крупнейшей ячейки | 0.666 |
| крупнейшие ячейки | LCN1\|PC 0.734, STARD10\|PC 0.672, BPIFB2\|PC 0.907, PITPNA\|PC 0.748, BPI\|PC 0.903, PITPNB\|PC 0.764, SEC14L6\|PC 0.877 |

Семь разных белков, не одна ячейка. Один выброс против — STARD2\|PC (0.368).

**Подвох.** `dataloader/pair_descriptors.py::tail_double_bond_position` по построению
возвращает `None` для полностью насыщенного липида — величины там не существует. Но
`dataloader/chemistry_prior.py::_lipid_descriptor_table` агрегирует как
`float(np.mean(vals)) if vals else 0.0`, то есть **`None` схлопывается в `0.0`**. В
таблице 26 видов из 283 насыщенные, и все они получают позицию 0 — неотличимо от
«двойная связь у самого метильного конца». Сигнал от этого не исчезает (на всех видах
0.651, на одних ненасыщенных 0.672 — то есть на смеси он слабее), но признак в текущем
виде смешивает две разные вещи. Это наблюдение, не правка.

## 5. Почему сеть этого не видит: узкое место — сжатие, а не вход

Базовая конфигурация кормит липидную сторону **PLM-эмбеддингом, сжатым до 10
измерений** (`plmon=True`, `plm_compression_dim=10`), и **ни одного** явного липидного
дескриптора (`descriptor_names` пусто, `lipid_descriptors` пусто,
`pair_descriptors=False`).

Проба: предсказать хвостовую величину из того же 768-мерного MolFormer-вектора, который
получает `lipid_encoder`, и из него же после PCA→10 (та же размерность, что у
`plm_compression`). Колонка «R² на остатках» — после вычитания среднего по подклассу,
то есть именно внутриклассовая вариация, та самая ось, на которой стоит задача.

| цель | вход | R² (group-CV по подклассу) | R² на остатках после класса |
|---|---|---:|---:|
| `tail_double_bonds` | 768 | +0.937 | +0.963 |
| | PCA→10 | +0.896 | **+0.855** |
| `tail_unsaturation_density` | 768 | +0.884 | +0.934 |
| | PCA→10 | +0.780 | **+0.849** |
| `tail_length_mean` | 768 | +0.690 | +0.821 |
| | PCA→10 | +0.467 | **+0.330** |
| `tail_double_bond_position` | 768 | +0.293 | +0.787 |
| | PCA→10 | +0.426 | **+0.092** |
| `tail_double_bond_position` (только ненасыщенные) | 768 | +0.793 | +0.875 |
| | PCA→10 | +0.720 | **+0.323** |

Порядок выживаемости в бутылочном горле 768→10:

```
число двойных связей    0.963 -> 0.855   переживает
плотность ненасыщенности 0.934 -> 0.849   переживает
длина цепи               0.821 -> 0.330   теряется наполовину
ПОЛОЖЕНИЕ двойной связи  0.875 -> 0.323   уничтожается
```

То есть сжатие вырезает ровно ту ось, у которой наибольший within-cell AUC, и оставляет
те, которые сильнее скоррелированы с классом. Это и объясняет, почему сеть садится на
маргинал «белок × подкласс»: вход, который до неё доходит, по сути и есть подкласс
(η²=0.75 по классу, [molformer_expressivity_probe.md](molformer_expressivity_probe.md)).

Это та самая проба, которую §5 `molformer_expressivity_probe.md` назвал «релевантнее
предыдущей» — с добавлением `tail_double_bond_position`, которого в том списке не было.

## 6. Неиспользованные сырые столбцы таблицы

Обучающий путь читает из интеракционной таблицы не всё. Два столбца не читает никто,
кроме препроцессинга и базлайнов:

**`ChainFragments` — годится.** Измеренная разбивка по sn-цепям (`(18:1/16:0)`),
непустая у 4942 из 9905 строк (49.9%) и у 162 из 283 видов. Производные:

| признак | within-cell AUC | пар |
|---|---:|---:|
| разница длин sn-цепей | 0.426 | 3583 |
| разница числа двойных связей между цепями | 0.468 | 3583 |

Разница длин (отклонение 0.074) сильнее, чем `tail_length_asymmetry` на том же месте
(0.527, отклонение 0.027) — потому что это **измеренное** назначение по sn, а не вывод
RDKit по неоднозначному мешку кандидатов. Цена — покрытие 50%.

**`Screen` — нельзя кормить, это утечка.**

| Screen | строк | поз | доля поз |
|---|---:|---:|---:|
| in cellulo | 4557 | 207 | 0.045 |
| in vitro | 5298 | 377 | 0.071 |
| in cellulo; in vitro | 42 | 42 | **1.000** |
| in vitro; in cellulo | 8 | 8 | **1.000** |

Пара, измеренная ОБОИМИ методами, положительна с вероятностью 1.000 (50 строк из 50) —
очевидно потому, что во втором эксперименте перепроверяли то, что попало в первом. Это
метаданные о том, как метка получена, а не свойство пары. Признак «in vitro» сам по себе
даёт within-cell AUC 0.461, то есть почти ничего; значение имеет только утекающий
индикатор «измерено дважды». Не кормить.

## 7. Предложения, по убыванию отношения «ожидаемая польза / цена»

Ни одно не реализовано; это предложения, не изменения.

**1. Явно подать `tail_double_bond_position` + отдельный флаг «насыщенный».**
Два числа вместо одного, чтобы не смешивать 26 насыщенных видов с «связь у конца»
(§4). Механизм понятен, within-cell AUC 0.672 при pooled 0.503 — информация по
построению сверх маргинала, и сжатие её сейчас выбрасывает. Самое дешёвое из всего
списка: дескриптор уже посчитан, нужен только проброс через `--descriptor_names`.
Заодно закрывает дыру в сетке: `tail_double_bonds` прогонялся
(`mlp_s15_nomb_hid32_m8_d21_tail_double_bonds.md`), `tail_double_bond_position` — ни разу.

**2. Не заставлять хвостовую ось конкурировать с классом за 10 измерений.**
Либо поднять `plm_compression_dim`, либо дать хвостовым дескрипторам обход сжатия
(отдельный вход, не через PLM-проекцию). §5 говорит, что это не вопрос «есть ли
информация во входе» — она есть; это вопрос пропускной способности. Второй вариант
предпочтительнее: ширина уже измерена и не помогает
(`hid128`, 2.97M параметров, ΔBA −0.011), а узкое место здесь — конкретный канал.

**3. Перенос приора между ячейками для тех 10.1%, где ячейки нет в трейне.**
Понижено в приоритете после пересчёта: BA на них 0.500, но позитивов там 2.9%, и
выбрасывание их целиком двигает приор лишь 0.871 → 0.879 (§2а). Нужна близость белков и
близость подклассов (ESM3/3Di и head-group Tanimoto — оба артефакта есть и в этой роли
не используются), но потолок выигрыша мал. Запас в +0.064 до оракула ячейки лежит не
здесь, а в крупных ячейках (§2б), и там он требует именно внутриячеечной информации,
то есть предложений 1–2.

**4. `ChainFragments` как sn-асимметрия.** Отклонение 0.074 при покрытии 50% (§6).
Дешёво, но половина строк останется без признака, так что нужен явный индикатор
покрытия, иначе пропуск превратится в ещё один «0.0, который значит две разные вещи».

**Чего делать не стоит.** Кормить `Screen` (§6, утечка). Добавлять ещё размерных
дескрипторов (`heavy`, `molar_refractivity`, `experimental_lipid_volume`,
`tail_heavy_atoms` — все в полосе 0.408–0.415, одна и та же ось размера, и она уже
наполовину проходит сжатие через `tail_length_mean`). Искать выигрыш в архитектуре
агрегации: 29 вариантов измерены, все внутри шума
([ge_s15_architecture_sweep_results.md](ge_s15_architecture_sweep_results.md)).

## 8. Чем посчитано

Готовых скриптов под эти пробы в `analysis/` нет; всё собрано драйверами из
существующих функций, в репозиторий не добавлялось:

- планка (§1) — **`analysis/protein_subclass_label_baseline.py --label ge_s15_prothid32_hid64_noreg`**,
  канонический скрипт; он же с дефолтным `mlp_s15_nomb_hid64` даёт то же 0.871 ± 0.009,
  поскольку сплит определяют только сид, `--negatives_per_positive` и
  `--balanced_proteins`, одинаковые в обоих arg-файлах;
- декомпозиция (§2) — `PLIDataset` на `arg_lines("ge_s15_prothid32_hid64_noreg")` по
  5 сидам с ТЕМ ЖЕ порогом `> 0.5` и тем же `protein_subclass_key`, подкласс из
  `dataloader.lipid_subclass_blocks.article_subclass_species`;
- within-cell AUC (§3–4, 6) — `dataloader.chemistry_prior._lipid_descriptor_table`
  (та же таблица, которую читает сам пайплайн) на полной интеракционной таблице;
- проба выразительности (§5) — `training.pair_baseline_common.molformer_lipid_features`,
  `RidgeCV` + `GroupKFold` по подклассу, PCA→10 как модель `plm_compression_dim=10`.

## 9. Что модель в этой конфигурации вообще не видит

`ge_s15_prothid32_hid64_noreg` читает с липидной стороны **один вектор**: MolFormer 768
измерений, сжатый до 10. Всё остальное на этой стороне выключено:

| канал | состояние | что это значит |
|---|---|---|
| `lipid_isomers`, `lipid_graph_isomers` | выкл | **химического графа липида нет вообще.** Модель не видит ни одного атома липида, ни одной связи — только одну точку в 10-мерном пространстве |
| `lipid_edge_mlp`, `lipid_edge_attention` | выкл | следствие предыдущего: нечему считать рёбра |
| `pair_descriptors`, `pair_descriptors_only` | выкл | ни одного из 14 парных дескрипторов (`volume_fit`, `chain_extent_gap`, `occupancy`, `tail_elongation_fit`, …) |
| `descriptor_names`, `lipid_descriptors`, `lipid_head_descriptors` | пусто | ни одного из 22 липидных дескрипторов, включая весь хвостовой блок §3 |
| `compatibility_input`, `pocket_compat_prior`, `chem_prior` | выкл | ни одного готового признака совместимости карман↔липид |
| `tanimoto_weight`, `grab_loss`, `hard_negative_mining`, `lipid_propensity_weight` | выкл | химическое сходство не входит ни во вход, ни в лосс, ни в сэмплирование негативов |
| `lipid_class_targets` | выкл | нет вспомогательной задачи на класс |
| `ChainFragments`, `Screen` (столбцы таблицы) | не читаются никем в обучающем пути | §6 |
| `esmif1` / `proteinmpnn` / `saprot` / `rnabang` / `protein_3di` | выкл | белковая сторона — только ESM3 + 14 дескрипторов кармана + граф |

Белковая сторона устроена сильно богаче липидной: граф с GATv2 и edge-MLP,
14 геометрических дескрипторов кармана, ESM3. Липидная — одна точка. Это и есть ответ на
«на что смотрит недостаточно»: асимметрия между сторонами тут не в пару процентов, а в
порядок.

## 10. Размер липида × глубина кармана: взаимодействие, которое нечем собрать

Структурный факт, ограничивающий поиск: **внутри ячейки белок постоянен**, поэтому
никакой чисто белковый признак внутри ячейки не может ничего различить. Информацию сверх
«белок × подкласс» могут нести только (а) липидные признаки и (б) ПРОИЗВЕДЕНИЯ белкового
на липидный. Из этого и строится §7.

Мера: within-cell AUC отдельно в каждой ячейке (только ячейки ≥20 пар, 54 ячейки,
28 белков), и дальше — разброс направления между ячейками.

| дескриптор | ячеек >0.5 | ячеек <0.5 | взвеш. AUC | ст. откл. по ячейкам |
|---|---:|---:|---:|---:|
| `tail_double_bond_position` | 38 | 15 | 0.653 | 0.200 |
| `unsaturation` | 17 | 36 | 0.355 | 0.201 |
| `chain` | 18 | 36 | 0.391 | 0.190 |
| `tail_length_mean` | 22 | 32 | 0.391 | 0.193 |
| `experimental_lipid_volume` | 22 | 32 | 0.412 | 0.205 |
| `logp` | 20 | 34 | 0.438 | 0.182 |
| `tail_length_asymmetry` | 21 | 21 | 0.527 | 0.172 |

Направление у размерных осей не универсально, и главное — **сила его разбросана
колоссально**. Свернув ячейки в белок (n=28, честнее — ячейки одного белка не независимы):
по `experimental_lipid_volume` within-AUC гуляет от **0.074 до 0.774**, по `chain` — от
0.037 до 0.666, и выше 0.5 оказываются лишь 5–6 белков из 28.

И этот разброс предсказуем геометрией кармана. Spearman между дескриптором кармана и
направлением сортировки белка по размеру липида, на уровне белка:

| липидная ось | лучший дескриптор кармана | ρ | p |
|---|---|---:|---:|
| `experimental_lipid_volume` | `depth_q10` | **−0.451** | 0.016 |
| `chain` | `depth_q10` | **−0.424** | 0.025 |
| `tail_length_mean` | `depth_q10` | **−0.381** | 0.046 |

Один и тот же дескриптор на всех трёх осях (а оси между собой сильно скоррелированы, так
что это одна находка, а не три). На уровне ячеек, где наблюдений больше но они зависимы,
к `depth_q10` добавляются `pocket_volume_per_sasa` (ρ −0.404, p=0.002) и `buriedness_q50`
(ρ −0.272, p=0.046) для `chain`.

**Почему модель этого не берёт.** `depth_q10` она получает — он в списке 14 дескрипторов
кармана. Размер липида она **не** получает: явных дескрипторов нет (§9), а из сжатия
768→10 длина цепи выходит с R² 0.330 на внутриклассовых остатках (§5). Перемножить
имеющееся на отсутствующее нельзя. Поэтому `depth_q10` может работать только аддитивно —
то есть как ещё одна координата белка, что внутри ячейки константа и не различает ничего.

Это аргумент в пользу предложения 1–2 §7 с другой стороны: даже если бы хвостовые
дескрипторы были нужны только ради произведения с геометрией кармана, подать их всё
равно необходимо — иначе вторая половина произведения отсутствует.

## 11. Что уже проверено и не сработало (не предлагать заново)

Внутри шума повтора (медиана 0.021), то есть «не сработало», а не «стало хуже». Так же

входа — одна десятимерная точка.
