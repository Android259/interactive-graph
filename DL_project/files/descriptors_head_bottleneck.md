# Голова `NamedDescriptorHead` — узкое место, а не дескрипторы и не сплит

Дата: 2026-09-29. Диагностика после сетки `dh_s15_mbw*` (11 лейблов) и лестницы
`_d11.._d14` (4 лейбла), все по 5 сидов, все завершились.

## 1. Главное

На **одном и том же** входе `descriptor_catalog_input` (11 стандартизованных колонок,
набор lcs-baseline, seed 0, блок species15 0.15, те же веса `marginal_balance_weight` ×
`class_weights`):

| модель | train BA | test BA |
|---|---:|---:|
| GBM depth 6 | 0.961 | 0.837 |
| MLP 64×64 | 0.922 | **0.853** |
| логистика без взаимодействий | 0.461 | 0.451 |
| **сеть `dh_s15_mbw_hid32_d11`** | **0.510** | **0.535** |

Обычный двухслойный MLP из тех же 11 чисел даёт 0.85. Голова проекта — 0.53 и не
подгоняет даже трейн. **Дело не в наборе дескрипторов, не в сплите и не в ширине.**

Подтверждающие факты:
- Вход исправен: все 11 колонок стандартизованы (mean≈0, std≈1), NaN нет, 35 белков
  дают ровно 35 различных кортежей белковых колонок.
- Путь данных верен: `descriptor_catalog_input` → `NamedDescriptorHead` → `binar`
  ([final_layer.py:717-734](../architecture/final_layer.py#L717-L734)), больше модель
  ничего не читает.
- Локальная копия головы воспроизводит кластер: train BA 0.520, test 0.511, loss 0.690
  против 0.510 / 0.535 / 0.669 в прогоне.
- Ширина не помогает: 1 538 → 58 882 параметров, min train loss везде 0.656–0.681,
  train BA 0.51–0.55. Ослабление регуляризации (wd 1e-5, dropout 0) тоже.

## 2. Подозреваемая причина

[named_descriptor_head.py:62](../architecture/named_descriptor_head.py#L62):

```python
self.token_embed = torch.nn.Linear(1, self.dim)   # ОДИН на все токены
self.token_identity = torch.nn.Parameter(...)     # [token_count, dim], константы
```

Токен t = `x_t·w + b + id_t`, где `w` общий для всех дескрипторов. Реакция на значение —
скаляр, умноженный на одно общее направление; отличаются токены только константным
сдвигом. Поэтому `hiddim` не покупает выразительности (арифметика подтверждена:
1538 − 1114 = 424 = 53 × 8, весь прирост — в `token_identity`), а внимание не может
выразить «volume_fit важен, когда карман вытянут».

**Не доказано.** Ablation (per-token вложение, `pool_type=mean`, lr, HEADS) прерван по
просьбе пользователя. Первый вариант успел отработать и лишь воспроизвёл проблему.

## 3. Что делать

1. **Прогнать лестницу дескрипторов** — аргфайлы готовы (§4). Ожидание по прошлому
   опыту: прироста не будет, `_d11.._d14` дали 0.535 / 0.543 / 0.530 / 0.500 против
   логистических 0.845 / 0.870 / 0.877 / 0.881. Это ещё одно подтверждение §1.
2. **Доделать ablation головы** — 8 вариантов по 40 эпох, параллельно, ~5 минут:
   как есть, lr 1e-3, lr 1e-2, wd 0, `pool_type=mean`, HEADS 4, per-token вложение,
   контрольный plain MLP. Скрипт: `scratchpad/one.py` сеанса.
3. **Если ablation подтвердит §2** — заменить общий `Linear(1, dim)` на per-token
   направление `[token_count, dim]` под новым флагом, старый путь по умолчанию.
4. **Альтернатива** — не чинить голову, а взять GBM/MLP как модель для этой задачи:
   `analysis/gbm_baseline.py` уже существует и на этом входе даёт 0.837.
