# Что модель выучивает и чего не выучивает

Сводка измерений на 2026-08-19: где сейчас стоит модель после закрытия утечки, какие
связи в данных найдены и что из этого следует делать. Все числа получены на честных
разрезах и, где отмечено, без отбора чекпойнта по валидации.

> **Правило сопровождения.** Числа тут — снимок конкретных прогонов, а не константы.
> Появились новые лейблы — пересчитать и заменить, а не дописать рядом. Скрипты, которыми
> всё считалось, перечислены в разделе 7; если правится любой из них, правится и этот файл.

## 1. Где стоит модель

Двусторонний холодный сплит (`--double_coldsplit`), 14 прогонов, 7 семейств × 2 сида,
последние 30 эпох валидации — то есть **без** отбора лучшей эпохи:

| | valid, посл. 30 | максимум за 120 | премия отбора | test |
|---|---|---|---|---|
| полная модель | **0.529** | 0.612 | **+0.083** | 0.563 |
| только липид | 0.493 | 0.526 | +0.032 | 0.511 |
| только белок | 0.500 | 0.511 | +0.011 | 0.505 |
| бейзлайн | 0.500 | — | — | 0.500 |

Холодный сплит по липидам (`--lipid_coldsplit`), 4 набора × 2 сида: valid посл. 30
**0.512**, максимум 0.594, test 0.575 — та же премия +0.082 и то же превышение над
бейзлайном в пределах сотых.

Обучающая выборка при этом выучена наизусть: train BA **0.937**, чувствительность 0.967,
специфичность 0.907, loss 0.07–0.24. Разрыв train/valid — **0.41**.

## 2. Утечка закрыта, и это проверяется в каждом запуске

Бейзлайн «доля положительных у этого липида в train больше 0.5» печатается в лог при
загрузке. По семи семействам, три сида:

| разрез | бейзлайн test | липидов test, виденных в train |
|---|---|---|
| односторонний по белку (как было) | 0.562 | 98.5 % |
| `--mixed_coldsplit` | 0.510 | 12 % |
| **`--double_coldsplit`** | **0.500** | **0 %** |
| **`--lipid_coldsplit`** | **0.500** | **0 %** |

До закрытия утечки всё, что модель показывала выше 0.5, объяснялось этим приором.
Подробности разреза — [double_cold_split.md](double_cold_split.md) и
[marginals_and_cold_split.md](marginals_and_cold_split.md).

## 3. Вторая утечка: отбор чекпойнта

Тестируется не последняя модель, а восстановленная из лучшего по валидации чекпойнта
([new_train.py:1596](../training/new_train.py#L1596)). Эпохи этого максимума разбросаны
равномерно, включая вторую и четвёртую:

```
dcs: 2, 4, 4, 4, 7, 12, 18, 28, 38, 39, 63, 76, 76, 99
mcs: 4, 4, 4, 10, 12, 12, 14, 23, 36, 72, 95, 115, 115, 116
```

Валидация за обучение не растёт: эпохи 1–30 дают 0.534, эпохи 91–120 дают 0.529. То есть
максимум — это аргмаксимум шума, и премия за него **+0.083** больше всего наблюдаемого
превышения над бейзлайном (+0.029). Премия масштабируется с тем, насколько модель варьирует
выход: у константы +0.011, у липидной половины +0.032, у полной +0.083 — то есть протокол
систематически льстит более шумной модели.

## 4. Найденные связи

### 4.1 Раскол по семействам — самое устойчивое, что есть

valid за последние 30 эпох, dcs:

| семейство | полная модель | только липид |
|---|---|---|
| LBP_BPI_CETP | 0.596 / 0.646 | 0.500 / 0.485 |
| scp2 | 0.597 / 0.622 | 0.495 / 0.487 |
| IP_trans | 0.566 / 0.536 | 0.470 / 0.497 |
| **среднее (работающие)** | **0.594** | **0.489** |
| GLTP | 0.514 / 0.507 | 0.517 / 0.483 |
| CRAL-TRIO | 0.499 / 0.453 | 0.519 / 0.504 |
| START | 0.455 / 0.471 | 0.486 / 0.486 |
| lipocalin | 0.469 / 0.475 | 0.494 / 0.483 |
| **среднее (ломающиеся)** | **0.470** | **0.495** |

Знак согласован во всех **12 прогонах из 12**: где белок помогает, он помогает обоим
сидам, где вредит — вредит обоим. Это не шум, это свойство семейства.

На работающей тройке разрыв полной модели и липидной половины **+0.105**, и он не может
прийти ни от липида одного, ни от белка одного (белковая половина константна). Это
единственное честное свидетельство парного сигнала, которое есть.

### 4.2 Чем различаются тройки — не установлено

Проверенные корреляции valid с характеристиками семейства (n = 7, для значимости нужно
|r| > 0.75 — ни одна не дотягивает):

| характеристика | r |
|---|---|
| число белков в отложенном семействе | −0.59 |
| число классов липидов с положительными | −0.51 |
| похожесть профиля на ближайшее другое семейство | +0.44 |
| разнобой профилей внутри семейства | +0.30 |
| выигрыш ESM3-соседей над константой | +0.13 |
| похожесть профиля ближайшего по ESM3 соседа | +0.05 |

Гипотеза «работает там, где у ближайшего в ESM3 белка похожий профиль» проверена прямо и
**отвергнута**: r = +0.05.

### 4.3 Геометрия белкового представления

595 пар белков, эмбеддинг ESM3 усреднён по остаткам — то, что получает модель:

| | медиана | диапазон |
|---|---|---|
| сходство ESM3 между белками | **0.974** | 0.905 … 1.000 |
| сходство профилей связывания | **0.000** | 0.000 … 1.000 |

Все 35 белков лежат в одной точке, а их поведение максимально различно. Корреляция одного
с другим **+0.227**.

Предсказание профиля отложенного объекта (косинус с истинным):

| | вынесен один белок | вынесено семейство |
|---|---|---|
| игнорировать белок (среднее по обучению) | 0.259 | **0.169** |
| три ближайших в ESM3 | **0.335** | **0.190** |

При семейном выносе — а модель работает именно так — знание о белке добавляет 0.169 → 0.190,
и у четырёх семейств из семи соседи **хуже**, чем игнорировать белок вовсе.

### 4.4 Что представление белка улучшить не смогло

| представление | предсказание профиля (вынесен один белок) | корреляция с профилем |
|---|---|---|
| ESM3, среднее по цепи | **0.335** | **+0.227** |
| ESM3, среднее по карману | — | +0.192 |
| 13 дескрипторов полости | 0.284 | +0.094 |
| 4 числа формы полости | 0.228 | −0.029 |
| ESM3 PCA5 + 13 дескрипторов | 0.291 | — |
| игнорировать белок | 0.259 | — |

Три проверенные идеи опровергнуты измерением: усреднение по карману вместо цепи корреляцию
**снижает**; дескрипторы формы предсказывают профиль **хуже**, чем игнорирование белка;
добавление дескрипторов к ESM3 результат **ухудшает**. Центрирование и выбеливание
эмбеддингов косинусный диапазон расширяют, но информации не добавляют (0.227 → 0.201) —
первый линейный слой это уже умеет.

### 4.5 Вырождение предсказаний

Класс-веса работают правильно: на обучении чувствительность 0.967 **выше** специфичности
0.907, то есть коррекция дисбаланса уже смещает в сторону положительных. На отложенном
блоке та же модель даёт чувствительность 0.03–0.22 при специфичности 0.90–0.97. Это не
дефицит калибровки, а дефицит информации: подвинуть порог можно, но BA останется у 0.5.

При `--protein_only` вырождение структурно неизбежно — липидная половина обнулена и
кросс-внимание выключено, значит все строки одного белка это один и тот же вход, а
`--balanced_proteins` обнуляет попротеиновый приор. Одиннадцать прогонов из четырнадцати
выдают константу. Этот бейзлайн проверяет проводку, а не ESM3.

## 5. Диагноз

Модель не выучивает ничего переносимого. Валидация не растёт ни на одной эпохе из 120,
абляция любой ветки почти ничего не меняет, предсказания сползают к мажоритарному классу,
а весь отчётный прирост над 0.5 — премия за выбор лучшей из 120 шумных оценок.

Причина не в архитектуре: 1 014 406 параметров на ~420 положительных строк — 2400
параметров на пример, и по белковой оси размер выборки **21–33**, а не 1200. Сигнал во
входе есть, но его мало (0.169 → 0.190 при семейном выносе), а ёмкости достаточно, чтобы
запомнить блок целиком (train BA 0.937).

Исключение, которое нельзя терять при усреднении: на LBP, scp2 и IP_trans парный сигнал
есть и он воспроизводим по сидам.

## 6. Что делать

**6.1 Сжать модель до размера данных.** Единственное, что ещё может превратить
«сигнала нет» в «сигнал есть». `--hiddim=8 --plm_compression_dim=8`, без третьих слоёв в
MLP, weight decay на порядок выше. Сотни параметров вместо миллиона запомнить 1500 строк
не могут, и модели остаётся пользоваться тем, что есть. Даст те же 0.51 — вопрос закрыт;
даст 0.55–0.58 устойчиво по сидам — сигнал был, и его топило запоминание.

**6.2 Убрать отбор чекпойнта.** Тест с последней эпохи вместо лучшей по валидации, или
скользящее среднее с минимальной эпохой. Пока премия +0.083 в протоколе, сравнение
архитектур смещено в пользу более шумной. Заодно считать AUC/AP вместо BA при пороге 0.5 —
при чувствительности 0.03–0.15 порог стоит не там, и BA перестаёт различать «не научилась»
и «порог не тот».

**6.3 Огрубить цель.** Предсказывать пару (белок, **класс** липида) вместо (белок, вид):
35 × 34 = 1190 ячеек вместо 11018 строк, метка опирается на десятки измерений вместо
одного. Задача остаётся бинарной. Сейчас из 101 фосфатидилхолина белок берёт либо почти
все, либо почти ни одного — то есть меток много, а независимой информации мало.

**Обновление (2026-09-04): проверено, отвергнуто.** `--lipid_class_targets` прогнан на
обоих актуальных бейзлайнах (bilinear_fusion+bilinear_pooled_norm, `--double_coldsplit`,
7×5) — test BA MLP 0.5525→**0.5195** (−0.033), attention (rim_ev28) 0.5514→**0.5478**
(−0.004, в пределах шума, но не в плюс). Огрубление цели не увеличило независимую
информацию так, как предполагалось выше: класс всё ещё наследует внутриклассовую
зависимость от вида, а число протеинов (реальное узкое место, §5) не изменилось. Рычаг
закрыт; не предлагать повторно без нового аргумента, отличного от изложенного здесь.

**6.4 Никогда не усреднять по семействам.** 0.529 не существует как свойство модели: это
смесь 0.594 на трёх семействах и 0.470 на трёх. Правка, оценённая по среднему, оценена
неверно. В отчётах — строка на семейство и две сводные цифры вместо одной.

**6.5 Зафиксировать отрицательный результат, если 6.1 ничего не даст.** Это ответ, а не
неудача: на 35 белках перенос на новое семейство и на новый класс липидов не решается, и
доказательство собрано — честный разрез, бейзлайн 0.500, модель 0.512, обе ветки на уровне
константы, представление белка добавляет 0.169 → 0.190. Тогда остаётся проверить, работает
ли модель там, где может — достройка матрицы внутри известных белков — и строить проект
вокруг этого.

**Чего делать не стоит:** крутить ёмкость белковой ветки ради борьбы с запоминанием
идентичности (between-protein variance 0.9 — следствие того, что ветке нечего больше
кодировать; идентичность 33 объектов помещается в одно вещественное измерение), заменять
ESM3 дескрипторами полости (измеримо хуже), искать больше белков (их нет).

## 8. `--descriptors_head`: pocket_extent не объясняет LBP_BPI_CETP, lipocalin — объясняет

Отдельная от разделов 1–7 архитектура (`training/read_configuration.py`, `ModelConfig.
descriptors_head` docstring): только `--pair_descriptors`+`--pocket_descriptors`, без
белковой/липидной ветки и cross-attention — sufficiency-проба «хватает ли одних
дескрипторов». Числа этого раздела относятся только к ней, не к «полной модели»
разделов 1–7, и не усредняются с ней.

На `descriptors_no_extent_coarse_add_lipprop` (test, epoch 120, `--double_coldsplit`,
`analysis/full_label_report.py --split test`) внутрибелковое приращение над химией
выделяет два семейства из семи:

| семейство | chem_prot | net_prot | increment_prot |
|---|---|---|---|
| **LBP_BPI_CETP** | 0.714 | 0.862 | **+0.165** |
| **lipocalin** | 0.459 | 0.536 | **+0.100** |
| остальные пять | 0.49–0.71 | 0.48–0.63 | −0.001…+0.041 |

LBP_BPI_CETP — то же семейство, что в project memory `[[descriptors-path-fingerprint-leak]]`
(`training/read_configuration.py:376-435`): на `descriptors_path` его test BA (0.796) не
объяснялась ни белко-слепой химией, ни нуль-моделью с богатым липидным входом. Два
опробованных фикса (`--no_pair_descriptor_pocket_shares`, `--pair_descriptor_pocket_
shares_split`) сделали разрыв **шире**, не уже. Третий, уже применённый именно в
`descriptors_no_extent_coarse_add_lipprop` (`--pair_descriptor_pocket_shares_coarse`),
тоже не закрыл его — BA вырос до **0.826**, increment_prot до **+0.165**.

**Проверено дёшево, без единого обучения**
(`analysis/pocket_extent_lbp_lipocalin_check.py`): следующий по очереди подозреваемый —
`pocket_extent` — **не объясняет LBP_BPI_CETP**. В форме, которую реально строит
`--double_coldsplit`-прогон (квартильные края, посчитанные на 33 белках БЕЗ LBP_BPI_CETP,
`--compat_extent_bins=4`), оба его белка попадают в ту же среднюю четверть, что медиана
остальных пяти семейств — доля белков, которых LBP_BPI_CETP обгоняет по банду: **0.48**
(0.5 = разделения нет). Значит `occupancy` (единственный канал, которым coarse_extent
доходит до дескрипторной головы под `--no_pair_descriptor_extent`) источником +0.165
быть не может.

**lipocalin — другая история.** Тот же чек даёт чистое разделение: доля обгоняемых —
**0.05**, все 10 белков в нижнем банде edges, посчитанных без них (сырой pocket_extent
тоже разделяет обе группы значимо: η²=0.256 против пола 0.029 для бинарного разбиения,
p=0.0028). `pocket_extent` — правдоподобный канал именно для lipocalin, не для
LBP_BPI_CETP.

**Значит:** источник LBP_BPI_CETP всё ещё не найден среди проверенных каналов (pocket_
shares raw/split/coarse, extent). Единственное, что дескрипторная голова читает и что
ещё не изолировано по отдельности, — четыре липид-only токена (chain/unsaturation/hbond/
heavy, `dataloader/pair_descriptors.py`); если это утечка, а не химия, она может быть по
липидной, не по белковой оси — специфичная для того, какие классы липидов исключены
именно на LBP_BPI_CETP (`Bismonoacylglycerolphosphate, Phosphatidylserine,
Phosphatidylinositol, Phosphatidylcholine`).

**Дальше:** `--pair_descriptor_extent` включён реальным прогоном
(`scripts/arg_files/descriptors_no_extent_coarse_add_lipprop_extent.md`) — если
increment_prot lipocalin упадёт, а LBP_BPI_CETP нет, гипотеза подтверждается прямым
измерением, а не только косвенным чеком выше.

## 9. `--bilinear_fusion`: `--bilinear_pooled_norm` чинит нестабильность, не разрыв sens/spec

`--bilinear_fusion` (`architecture/final_layer.py`) заменяет конкатенацию пула
белка/липида на `torch.nn.Bilinear(lip, prot)` — интерактивный вектор, из которого не
выжить отпечатку одного партнёра. У этого произведения нет верхней границы, а
`pool_type="add"` (дефолт) суммирует разное число узлов на образец (атомы липида,
остатки кармана), так что масштаб `lip_outs`/`prot_outs` и без того плавает от строки
к строке. Четыре прогона на `geometric_edge_mlp_protgeom_family_neutral*`,
`--double_coldsplit`, 7 семейств × 5 сидов:

| вариант | test loss (mean/max) | gap sens/spec (mean/median) | ckpt_epoch↔log(loss), r | max valid BA |
|---|---|---|---|---|
| без bilinear | 0.77 / ~2 | 0.51 / 0.40 | — | 0.647 |
| bilinear, сырые pocket-дескрипторы | 8.09 / 137 | 0.41 / 0.36 | −0.64 | 0.660 |
| bilinear, нормализованный вход (`--protein_descriptors=`) | 7.01 / 93 | 0.46 / 0.41 | −0.64 | 0.656 |
| bilinear, нормализованный вход + `--bilinear_pooled_norm` | **0.73 / 1.55** | **0.59 / 0.59** | **+0.38** | 0.608 |

**Нестабильность закрыта конкретным механизмом, не входными данными.** Корреляция
между эпохой выбранного чекпойнта и test loss держится на −0.64 что с сырыми, что с
нормализованными pocket-дескрипторами — вход был не при чём. `--bilinear_pooled_norm`
(`LayerNorm` на `lip_outs`/`prot_outs` перед произведением, `training/read_
configuration.py`, `architecture/final_layer.py`) убирает выбросы почти полностью
(max loss 137→1.55) и переворачивает знак корреляции — лотерея с ранним, ещё не
устоявшимся чекпойнтом больше не работает.

**Но разрыв sens/spec на тесте стал хуже, а не лучше: 0.59 против 0.41–0.51 у всех
остальных вариантов**, и это не случайный выброс — специфичность выше чувствительности
одинаково во всех 7 семействах (тест: sens 0.29 / spec 0.82 в среднем). Три проверки,
почему, и что из этого следует:

1. **Не проблема `--balanced_batches`/`--balanced_proteins`/`--class_weights`, но по
   разным причинам.** `--balanced_batches`/`--balanced_proteins` — это сэмплер
   (`training/new_train.py:239-261`, `ClassBalancedBatchSampler`; `dataloader/
   Dataloader.py:1375`, `split_and_sample_protein_balanced_interactions`) — состав
   батча/датасета фиксируется ДО того, как модель вообще запустится, от масштаба
   выхода сети никак не зависит; при этом `--balanced_batches` НЕ выравнивает батч до
   50/50 — при дефолтном `negatives_per_positive=2` он сохраняет исходное соотношение
   (комментарий `new_train.py:246-251`: 2 позитива + 4 негатива на `--batch=8`, не 4+4).
   **Поправка:** `--class_weights` (`training/new_train.py:183-188`) по умолчанию
   `True` (`training/read_configuration.py:1094`) и явно не выключен ни в одном из двух
   arg-файлов — значит он был включён в обоих, а не отключён, как написано здесь раньше.
   При `negatives_per_positive=2` формула даёт вес ≈[0.75, 1.5] (негативы, позитивы) —
   позитивный класс уже подтянут в полтора раза. Вывод от этого не меняется, но по
   другой причине: `class_weights` — фиксированное число, посчитанное один раз из
   `class_counts` (числа меток в train), не из выхода сети, значит рассинхронизация с
   масштабом bilinear-выхода структурно невозможна что при включённом флаге, что при
   выключенном. А раз вес уже тянул в сторону позитивного класса и это не помогло —
   это более сильный, а не более слабый довод в пользу дефицита информации ниже:
   модели явно помогали чувствительности, и она всё равно её потеряла на тесте.
2. **train у нормализованного прогона сбалансирован** (train sens 0.69 / train spec
   0.63, ALL) **— разъезжается только на тесте.** Тот же почерк, что в разделе 4.5
   этого файла для более ранней конфигурации (train sens 0.967 ≫ spec 0.907, test sens
   0.03–0.22 против spec 0.90–0.97) — там это было измерено и названо не дефицитом
   калибровки, а дефицитом информации на отложенном семействе. Совпадение почерка на
   independent архитектуре — дополнительное свидетельство за тот же диагноз, а не
   новая проблема, изобретённая нормализацией.
3. **У нестабильного варианта тот же перекос был, просто размазан по знаку.** Сырой
   bilinear в среднем показывал sens/spec 0.58/0.57 — на вид сбалансированно, но по
   семьям в одну сторону (`groups_START` sens 0.65/spec 0.33), в другую
   (`groups_LBP_BPI_CETP` sens 0.55/spec 0.73), std по specificity 0.27. `--bilinear_
   pooled_norm` не создал перекос — он убрал шум, который эти разнонаправленные
   перекосы усреднял в мнимый баланс, и во всех семьях проступило одно и то же
   направление.

**Предложения дальше (ни одно не пробовано):**

1. **`--bilinear_weight_decay` поверх `--bilinear_pooled_norm` сейчас не нужен.** Это
   была вторая мера против того же симптома (нестабильность), симптом уже закрыт
   структурно — держать про запас на случай, если LayerNorm понадобится смягчить, а не
   тратить сразу.
2. **Пересчитывать `--balanced_batches`/`class_weights` под новый масштаб логитов —
   не тот рычаг**, см. пункт 1 разбора выше: `class_weights` уже включён по умолчанию
   и уже тянет в сторону позитивного класса (≈1.5×), но зависеть от масштаба выхода
   сети не может ни один из трёх механизмов — балансировка выборки и весовая формула
   считаются из меток, до прогона модели. Разрыв — это generalization-дефицит на
   отложенном семействе (тот же, что в §4.5), а не рассинхронизация весовой схемы с
   новой архитектурой.
3. **Огрублять цель до класса липида, а не вида** (§6.3 выше) — раз разрыв это
   дефицит информации на семью, а не проблема балансировки, это бьёт в причину прямо:
   больше независимых меток на ячейку, задача остаётся бинарной.
4. **Более мягкая альтернатива `LayerNorm`** — max valid BA у нормализованного
   варианта тоже просел (0.656→0.608), то есть не только шум ушёл, но и потолок
   обучаемости. `LayerNorm` фиксирует единичную дисперсию по каждому признаку жёстко;
   L2-нормализация с одним обучаемым скаляром масштаба на ветку — мягче, не проверялась.

(типичная кривизна одного прогона). Разрыв между агрегированными sens/spec строки

и может двигаться в противоположную сторону: у attention+2 дескриптора первое
УЛУЧШИЛОСЬ (0.518→0.446 относительно attention без них), а второе УХУДШИЛОСЬ
(0.336→0.440) — sensitivity по ALL просела 0.375→0.331, specificity выросла
0.711→0.771. Модель стала ровнее от прогона к прогону (std sensitivity 0.279→0.196),
но систематическое смещение к «нет» усилилось. Разница не в том, какая метрика
«правильная» — они про разное (типичный единичный запуск vs агрегат по всем сразу),
но использовать одну как единственный критерий «лучше/хуже» без другой — способ
сделать неверный вывод, как это и произошло здесь один раз.

**Перекос в specificity — не из-за состава теста.** Проверено прямо: доля позитивов
в тесте по семьям 0.33–0.52 (`label_positive_fraction`, `metrics_summary.csv`), и
корреляции с силой перекоса нет — GLTP при идеально сбалансированном тесте (0.50)

ОДИНАКОВЫМ составом теста (0.33) дают разные по силе перекосы (0.38 против 0.74)

«без сигнала»: у семьи без переносимого сигнала решение скатывается к фону обучения
(`--negatives_per_positive=2` даже после поправки `--class_weights`, см. пункт 2 §9
выше, остаётся смещён к «нет»), у семьи с сигналом (тут — CRAL-TRIO, mildest gap
0.25) фон переопределяется. Сила перекоса по семье — косвенный градусник того,
сколько у неё вообще есть переносимого сигнала, а не артефакт разметки.

## 11. Рычаги, не завязанные на ёмкость модели

§6.1 предполагал, что проблема — переизбыток параметров при недостатке протеинов (2400
параметров/пример). Но раскол по семействам (§4.1) и геометрия ESM3 (§4.3–4.4) говорят
о другом: сигнала в представлении белка мало **независимо** от того, сколько у модели
параметров — сжатие `hiddim` борется с запоминанием, а не добавляет информацию на
входе. На 35 белках маловероятно, что урезание ёмкости само по себе раскроет сигнал,
которого измеримо нет ни в ESM3-косинусах (медиана 0.974 между максимально разными по
поведению белками, §4.3), ни в дескрипторах кармана (§4.4). Дальше — то, что либо
достаёт больше сигнала из входа, либо честнее его использует, либо меняет саму
постановку задачи, а не то, что урезает модель.

### 11.1 `--group_dro` изолированно — уже есть намёк, что работает

`geometric_edge_mlp_protgeom_family_neutral_dro_wd01` (3 из 5 сидов,
`graphics/geometric_edge_mlp_protgeom_family_neutral_dro_wd01/...md`) добавил
одновременно `--group_dro` и `--weight_decay=0.1` (×10 к дефолту) поверх бейзлайна
**без** bilinear_fusion. test BA не изменился (0.562 против 0.552–0.555 у бейзлайна и
у всех прогонов этой ночи — в пределах шума), но ALL sens/spec выровнялись до
**0.519/0.606** — против обычных 0.28–0.35/0.76–0.83 у бейзлайна и у всех четырёх
прогонов §10, завершённых этой ночью. Это первый прогон в проекте, который заметно
снимает патологию [[sens-spec-coldsplit-asymmetry]] за счёт обучения, а не сдвига
порога решения.

Не изолировано: изменены сразу два параметра (`group_dro` и `weight_decay`), плюс
отсутствует bilinear_fusion/rim_ev28 — бейзлайн для сравнения другой, не тот, что во
всех прогонах §10. **Предложение:** два прогона на актуальном bilinear_fusion+
bilinear_pooled_norm+rim_ev28 бейзлайне, 5 сидов × 7 семейств: (a) только
`--group_dro` (`--weight_decay=0.01` как везде), (b) только `--weight_decay=0.1` без
`--group_dro`. Если ребаланс держится у (a) и пропадает у (b) — источник найден, и это
прямая правка симптома §4.5/§9.2 (решение скатывается к фону обучения на семьях без
сигнала): `--group_dro` буквально штрафует худшую по батчу группу, что должно
противодействовать именно этому скатыванию, а не капацитету.

### 11.2 Transductive-сплит — рассмотрено и отклонено (2026-09-04), эксперимент не нужен

Была идея: вместо переноса на новое семейство проверить достройку матрицы внутри уже
известных белков (случайный тёплый сплит вместо `--double_coldsplit`). Отклонена по
двум причинам, вторая — решающая.

**(1) Не бесплатно.** По коду (`dataloader/Dataloader.py:1404-1488`) при
`--double_coldsplit` `valid` и `test` — два случайных куска **одной и той же отложенной
семьи**; ни один белок из train в valid не попадает, готовый чекпойнт для этого не
годится. Тёплый сплит — это дефолт при отсутствии `--double_coldsplit`/
`--lipid_coldsplit`/`--mixed_coldsplit` (`Dataloader.py:1416`,
`csvtrain = self.csvt.sample(frac=0.85, ...)`), но нужен новый прогон.

**(2) Результат ничего не докажет — заранее известен.** При 33–35 белках, глобальном
пулинге (§4.3–4.4) и `bilinear_fusion` на выходе ничто не мешает сети выучить не
биофизику, а низкоранговую матрицу склонностей белок×липид — collaborative filtering по
идентичности вместо структуры. На тёплом сплите такая матрица неизбежно даст BA заметно
выше 0.5: это тот же липидный приор из §2 (утечка через маргиналы), только двумерный и
пропущенный через сеть, а не явная таблица. Ничего нового это не скажет — train BA уже
0.937 (§1) чистым запоминанием, и что модель способна воспроизвести обучающие данные,
если её отпустить с обучающими же сущностями, известно и без нового прогона. Не делать.

### 11.3 Заменить argmax-отбор чекпойнта усреднением предсказаний, а не окном

§3 диагностировал премию отбора (+0.083); `--checkpoint_window=30` (§10) её не снял.
Не пробовано: усреднять не BA по окну эпох (что уже не сработало), а сами вероятности
предсказаний по последним N чекпойнтам перед решением на тесте (temporal/checkpoint
ensembling). Это меняет протокол оценки, а не архитектуру или вход, и в отличие от
hid4 не требует, чтобы в данных было больше сигнала — снижает только дисперсию оценки
одной и той же модели.

### 11.4 Обогатить протеиновую ветку без global average pooling

§4.4 закрыл три идеи (карман вместо цепи, дескрипторы формы, добавление дескрипторов к
ESM3) — но все три производные от одного и того же усреднённого по цепи представления.
Не пробовано: представление, которое не проходит через global average pooling ДО
входа в модель — например, обучаемый attention-пулинг по остаткам кармана (не путать с
уже проверенным фиксированным «средним по карману», §4.3, которое снизило корреляцию).
Обучаемые веса пулинга могут выделить именно ту часть цепи, где сосредоточен сигнал,
вместо того чтобы размывать его усреднением до того, как модель вообще его увидит.

**Обновление (2026-09-04): проверено на четырёх вариантах, эффекта нет.** Поверх того
же MLP-edges бейзлайна (`geometric_edge_mlp_protgeom_family_neutral_normalized_
bilinear_fusion_bilinear_norm`, 7×5, `--double_coldsplit`, `--bilinear_pooled_norm`):
`attnpool` (`--attention_pooling` — сама идея этого раздела, обучаемый attention-пулинг
вместо global average), `attnpool_pocketbias` (+ `--attention_pooling_pocket_bias`),
`attnbypocket` (`--attention_by_pockets --pocket_attention_sites=self` — внимание
ограничено карманом, без обучаемого пулинга) и `pocketonly` (`--protein_pockets_only`,
не из этого раздела, но той же идеи «не пулить по всей цепи усреднением»):

| вариант | test BA (n=35) | Δ к бейзлайну | sens/spec | max valid BA |
|---|---|---|---|---|
| бейзлайн (MLP-edges) | 0.5525 | — | 0.286/0.819 | 0.608 |
| attnbypocket | 0.5477 | −0.0048 | 0.305/0.791 | 0.607 |
| attnpool (сама идея раздела) | 0.5377 | **−0.0148** | 0.303/0.773 | 0.599 |
| attnpool_pocketbias | 0.5442 | −0.0083 | 0.304/0.784 | 0.607 |
| pocketonly | 0.5564 | +0.0039 | 0.350/0.763 | **0.632** |

Все четыре Δ лежат внутри типичного per-group std (0.06–0.09 в этих же прогонах, §10) —
статистически неотличимо от шума. Сама идея раздела (`attnpool`) не просто не помогла —
она единственная из четырёх ушла в минус за пределы трёх остальных.

Разбивка по семьям воспроизводит уже известный раскол §4.1 без исключений: у всех трёх
attention-pooling вариантов GLTP и START проседают (GLTP 0.536→0.480/0.452/0.460, START
0.522→0.473/0.490/0.491), IP_trans и LBP_BPI_CETP растут (IP_trans
0.574→0.628/0.609/0.622, LBP_BPI_CETP 0.580→0.597/0.602/0.581) — тот же знак, что у
бейзлайна, просто сильнее в обе стороны. `pocketonly` — единственный, кто не проседает
на GLTP (0.544, чуть выше бейзлайна) и даёт лучший max valid BA (0.632) из всех пяти, но
и он внутри per-group шума по итоговому test BA.

**Вывод.** Ни обучаемый attention-пулинг, ни ограничение внимания карманом (в обоих
вариантах) не достают сигнал, которого измеримо нет в усреднённом по цепи представлении
(§4.4). Рычаг закрыт тем же способом, что §6.3 и рычаги §10 — не предлагать повторно без
нового аргумента, отличного от изложенного здесь.
